# 修复：任务历史清理按 mtime 整文件删除与失败记录误导文案

## 问题背景（用户报告，来自 2026-10-02 全面排查清单第 1、2 条）

1. `_cleanup_old_logs` 在服务初始化与每日维护任务（`_job_maintenance`）中按 **文件 mtime** 删除
   超过 3 天的整个 `history/*.json`：某任务只要超过 3 天没有执行（例如任务停用、账号离线、
   连续失败中断），其**全部运行历史即被清空**，历史面板只剩"暂无历史执行日志"，
   与"保留最近 N 条"的用户预期不符。
2. 任务历史面板中，`message` 为空的**失败**记录渲染为
   "该记录没有流程详情（旧版本可能仅保存结果）"——这是一个信息性提示文案，
   用在失败记录上让用户无法得知"这次失败了但没有原因记录"，误导排障方向
   （用户 10/1 19:22:55 的失败记录即如此显示）。

## 根因分析

- R1：`_cleanup_old_logs` 用 `log_file.stat().st_mtime < limit` 判断删除整个文件，
  把"文件的最后写入时间"当成了"所有条目的时间"。文件 mtime 只反映最后一次写入，
  不代表其中旧条目都已过期；反之长期未写入的文件里仍可能有 3 天内的有效条目语义
  （条目时间与文件时间解耦）。
- R2：前端 `page.tsx` 两处 `{log.message || t("task_history_no_flow")}` 对空 message
  一律显示"没有流程详情"提示，未区分成功/失败记录。

## 修复目标

1. 历史清理改为**按条目 `time` 裁剪**：删除超过 3 天的条目，仍有保留条目时原子写回文件，
   全部过期才删除文件；条目时间缺失/无法解析的保守保留（由 `_history_max_entries` 条数上限
   兜底裁剪）；文件损坏或非列表旧格式退回原 mtime 删除行为。
2. 失败且无 message 的记录显示"失败（无详细原因记录）"；成功且无 message 的记录保留原
   "没有流程详情"提示。新增中英文案 key。

## 验收标准

- 回归测试：混合新旧条目的历史文件清理后仅保留新条目且文件存在；全旧条目文件被删除；
  缺失/非法时间条目被保留；损坏文件按 mtime 删除。
- 现有测试套件全部通过。
- 前端文案变更无自动化组件测试基础设施，以代码走查 + 手工核对双语 key 记录验证
  （`LanguageContext.tsx` zh/en 两处 key 成对存在、`page.tsx` 两处渲染点均按 success 区分）。
