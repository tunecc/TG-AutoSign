# 目标

简化任务中心的"创建任务"体验：新增"快速创建"入口，用户不需要理解 chats/actions/cron 等高级配置，即可一键为所有账号批量创建"每小时签到 + 发消息"任务：

- 蓝色/金鼎/绿色是 3 个机器人的别名（chat_id 分别为 7460869927 / 5969411283 / 6379863842）。
- **所有**面板账号都要对这 3 个机器人分别执行：先发 `/qd`（签到），随机等待 60~600 秒（可配置），再发 `/hz 15070527892 5`（命令原样发给机器人）。
- 每个账号每小时完成一轮全部机器人的签到，全天 24 小时覆盖；小时内随机时刻执行（触发点 + 随机延迟）。
- 执行频率（每 X 小时）与随机间隔（min~max 秒）均可自行设置。

现状调查结论（2026-11-21，基于 main）：

- 任务中心 = `frontend/app/dashboard/sign-tasks/` 管理的签到任务（SignTask，文件 JSON 存储，不进 SQLite）。
- 执行引擎 `tg_signer` 已完整支持目标场景，无需改动引擎：
  - `SignConfigV4.sign_at` 支持 cron（如 `0 * * * *` 每小时触发）。
  - `random_seconds`：调度执行（run_once）前随机延迟 0~N 秒（`tg_signer/core.py:1607`），实现"小时内随机时刻"。
  - `SignChatV4.action_interval_mode=random` + `action_interval_min_ms/max_ms`：同一会话内动作之间的随机间隔（`tg_signer/core.py:1492-1501`），覆盖 `/qd` 与 `/hz` 之间的随机等待。
  - 动作 `SEND_TEXT` 可发送任意文本命令（`tg_signer/config.py:193`）。
  - 一个任务可含多个 chats（每 bot 一个 chat），chat 间由 `sign_interval` 控制间隔；每账号一个任务即可覆盖 3 个机器人。
- 复杂度集中在创建/编辑 UI（chats、actions、cron、间隔全部暴露给用户）与后端 `create_task` 参数（`backend/services/sign_tasks.py:948-1041`）。

# 已确认决定

- D1（Q1）：蓝色/金鼎/绿色为机器人别名；所有账号对 3 个机器人执行 /qd 和 /hz；15070527892 是 /hz 的命令参数，随命令原样发送。
- D2（Q2）：小时内随机时刻执行（每小时触发 + 随机延迟）。
- D3（Q3）：新增"快速创建"，保留现有高级创建/编辑/模板，不做迁移。
- D4（Q4）：动作间隔默认 60~600 秒随机，可修改。

# 范围

## 修改

- `backend/services/sign_tasks.py`：新增快速创建服务方法：输入账号列表、机器人清单（别名+chat_id+命令序列）、频率（小时数）、小时内随机延迟上限、动作间隔 min/max 秒；映射为每账号一个 SignTask（chats=机器人清单，actions=命令序列，cron 每小时触发，random_seconds=小时内延迟上限，action_interval=random）。
- `backend/api/routes/sign_tasks.py`：新增 `POST /api/sign-tasks/quick-create` 路由（请求 schema 见 schemas）。
- `backend/schemas/`：快速创建请求/响应 schema。
- `frontend/app/dashboard/sign-tasks/`：任务中心新增"快速创建"页/入口（默认首选入口），含账号多选（默认全选）、机器人清单编辑（预填蓝色/金鼎/绿色三组及命令）、频率与间隔设置；提交后展示创建结果（成功/失败各账号）。
- `frontend/lib/api.ts`（或等价 API 封装）：新增 quick-create 调用。

## 明确不建

- 不改动普通任务（DB tasks）体系与监控任务。
- 不改动 tg_signer 引擎核心调度/动作执行逻辑。
- 不迁移、不删除已有签到任务配置；高级创建/编辑/模板功能保持现状。

# 非目标

- 不支持除"每小时/每 X 小时 + 随机延迟"以外的调度模式（自定义 cron、每天固定时刻等仍走高级创建）。
- 不改变任务运行历史、日志、通知等既有可观测行为。
- 不新增动作类型（只使用现有 SEND_TEXT）。

# 验收示例

- A1: 在快速创建页默认状态下（账号全选、机器人预填蓝色/金鼎/绿色三组及命令 `/qd`、`/hz 15070527892 5`、每小时、间隔 60~600 秒）提交后，每个所选账号各生成 1 个签到任务；每任务包含 3 个 chats（对应 3 个机器人），每 chat 动作依次为 `/qd` 与 `/hz 15070527892 5`。
- A2: 生成的任务调度为每小时触发一次（全天 24 次覆盖），且配置了小时内随机延迟（random_seconds>0），实际执行时刻在触发小时内随机分布。
- A3: 生成的每 chat 动作间隔为 random 模式且 min=60s、max=600s；把间隔改为其他范围（如 30~120 秒）后提交，生成配置相应变化。
- A4: 把频率改为每 2 小时后提交，生成任务每天触发 12 次（全天仍覆盖），随机延迟上限相应调整且不超过触发间隔。
- A5: 现有高级创建/编辑/模板功能不受影响（现有页面可正常打开并创建/编辑任务）；既有任务配置文件未被修改。
- A6: 快速创建提交后，界面展示每个账号任务的创建成功/失败结果；部分账号失败时其余账号任务仍创建成功。
